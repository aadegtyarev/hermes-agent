## `/hermes_program` в личке с ботом молчит, даже для глобального админа

**Статус:** открыто, не делать без отдельного запроса.

Личный чат с ботом (DM) для `/hermes_program` специально закрыт ещё в
PR #30 (программа/клиентский чат — это всегда групповой чат, не личка),
но ответ при этом — полная тишина, даже если пишет глобальный админ
(`TELEGRAM_ADMIN_USERS`). Для постороннего это правильное поведение (не
светить механизм), но для самого админа выглядит как «команда не
работает» — с этого и начался репорт.

Код: `deploy/multi-agent/base/plugins/telegram-context/__init__.py`,
`_handle_command()`:

```python
if cmd == "/hermes_program":
    if ctype == "dm":
        return _NON_ADMIN_SILENT   # тишина для всех, включая админа
    return _handle_hermes_program(chat_id, uid, title, text)
```

Смежная, отдельная, уже существующая (не регрессия) особенность: `/help`
вообще не показывает `/hermes_*` команды (и `hermes_here`/`hermes_readonly`/
`hermes_forget`/`hermes_chats` — тоже) — `gateway_help_lines()` в
`hermes_cli/commands.py` строится только из `COMMAND_REGISTRY`, плагинные
`register_command()`-команды туда не попадают. Видны только в нативном
Telegram-меню «/» (и то не в группах — там меню специально держат пустым).

### Предлагаемое исправление
В `_handle_command()`, кейс `ctype == "dm"` для `/hermes_program`:
- если `uid` — глобальный админ (`uid in _admin_users()`) — ответить
  подсказкой («нужна группа — чат команды программы или клиентский чат,
  не личка с ботом»), а не молчать;
- для НЕ-админа оставить полную тишину как есть (не раскрывать механизм
  посторонним).

Отдельно, опционально (не блокирует фикс выше): подумать, не стоит ли
`/hermes_*` командам как-то попадать хотя бы в `/help` для админа — сейчас
единственный способ узнать синтаксис — смотреть код/доку
`skills/telegram-guide`.

### Как воспроизвести
1. Написать боту в личку `/hermes_program` (с любым аргументом или без).
2. Ответа нет вообще, в `/help` команда тоже не упоминается.
